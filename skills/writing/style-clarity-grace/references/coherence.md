# Coherence — paragraphs and the whole

Cohesion is sentence-to-sentence. Coherence is whether the reader can
name **what the passage is about** and **what it claims**.

(Williams and Colomb treat this at paragraph and document scale.)

## Paragraph test

After reading a paragraph, the reader should answer:

1. What is this paragraph about? (consistent topics)
2. What is the point? (one claim, recommendation, or finding)

If those answers are fuzzy, the paragraph is a pile of true sentences.

## Point sentence

Put the point early unless you have a reason to land it at the end
(you are building a proof the reader will resist). LLM default is
neither: a soft opener, a wander, a restated closer.

- Findings / docs: point first.
- Argument the reader will fight: evidence, then the point.
- Never: point, wander, same point again.

## Topic string

List the subjects (or opening phrases) of each sentence in the
paragraph. They should be a short set — one character, or a small
cast that the point requires.

Bad topic string: *It / There / This / One / The fact / It*.
Better: *The consumer / It / The lease / The consumer*.

If every sentence opens on a new abstraction, the paragraph has no
aboutness, only sequence.

## Document scale

Readers need a sense of the whole before the parts:

- First screen states the job (finding, recommendation, map).
- Headings advance claims, not labels (`Why replay ignores the first checkpoint`,
  not `Overview`).
- Sections that could be shuffled are not a document; they are a list.

This matches **writing-technical** “payload early” and “structure does
the thinking.” Use that skill for the skeleton; use this one when the
skeleton is right and the paragraphs still don’t cohere.

## Open gaps stay open

A coherent paragraph can end on an unanswered question. Coherence is
not a tidy summary. It is a namable point — including “we don’t know X.”
